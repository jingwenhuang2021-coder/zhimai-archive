# 织唛 · GTM 驾驶舱

把现有企业诊断中的经营反馈、竞品采样、方法建议与执行动作，组织为可更新的 GTM 工作空间。

## 页面结构

- 项目总览：当前验证重点、待决策问题、关键任务与业务目标。
- 六个阶段：供给与经营底线 → 市场与客户 → 产品与方案 → 获客与询盘 → 成交与交付 → 复购与复制。
- 任务中心：阶段、业务线、优先级、状态、负责人、日期、交付物、结果与证据。
- 证据库：经营反馈、方法建议、公开采样、工厂确认、客户访谈、实际订单、实测记录与 AI 实践。
- 决策记录：选项、当前方案、依据及关联任务。
- 比价与测算：保留墨西哥和西班牙样本，按五个数量档分别保存成本输入。
- `diagnosis.html`：原企业诊断完整保留，原图片和历史资讯路径保持不变。

## 使用与保存

第一版是无后端的浏览器应用。基线资料来自 2026-10-25 的企业诊断与已完成采样，GTM 结构整理于 2026-10-26。

编辑内容保存在当前站点、当前浏览器的 localStorage 中（`zhimai-gtm-v1`）。同一浏览器的其他标签页可同步更新。不同设备、不同浏览器或不同站点来源之间不会自动同步。

使用右上角“导出备份”下载 JSON；在另一设备通过“导入”恢复。导入会校验数据并要求确认替换。导入前的状态另存为本机内部恢复副本；平常仍应保留导出的文件。清除浏览器站点数据可能丢失编辑内容。

本应用不会把个人输入、报价、联系人或订单自动提交至 GitHub；仓库与页面沿用已有公开访问方式。后续若增加云端数据同步，应另行设计身份与访问控制。

任务日期用于记录计划，不会自动发送推送或邮件提醒。客户独立站、自动报价、真实业务线索和订单系统均未在本驾驶舱中虚构为已完成。

## 判断边界

- 只有已核实完成的首轮竞品采样预置为“已完成”；旧任务执行情况不明时保留“待确认”。
- 完成任务需要填写实际结果；阶段验证和采纳决策分别要求结论／选择及关联证据。
- 阶段状态由使用者依据证据更新，不由任务百分比自动推断。
- 公开采样仅为两个产品参考，不代表国家市场规模、采购需求或实际成交价。
- 成本计算中，空白代表未知，明确没有的费用填写 0。缺项时不显示完整贡献或利润判断。
- 测算收入由使用者输入；不会自动把竞品零售价作为自己的销售收入。
- 贡献计算不替代实际订单复盘，未列入的固定经营费用仍须考虑。

## 文件与发布

GitHub Pages 根目录使用 `index.html`、`cockpit.css`、`cockpit-data.js` 与 `cockpit.js`；原图片和资讯目录保留。开发预览的 `dist/` 内容映射到仓库根目录。

无外部脚本、字体或依赖，无构建步骤。浏览器需启用 JavaScript。

## 已完成验证

- JavaScript 语法及基线关联完整性。
- 浏览器实际检查任务新增、搜索、结果必填、刷新保存与决策关联。
- 浏览器实际检查证据新增、决策采纳校验与阶段结论校验。
- JSON 导出、字段保留、导入确认与恢复。
- 500 枚测试情景：净收入 1,000 元、完整列入成本 300 元，贡献 700 元、贡献率 70%。测试数据不写入发布基线。
- 390px 框架内检查手机布局，页面无横向溢出；任务表保留独立横向滚动。

新增功能仍应沿用“业务事实、待验证判断、建议动作”分开的原则。
